# Remote prospective Binance Vision daily source contract

Frozen source-only activation: **2026-11-13 00:00 UTC**. This is a data journal, **not** a trading-hypothesis preregistration, Alpha result or live trading authorization. Its daily files must not be used to claim earlier availability than `captured_at_utc`.

## Source and scope

- [Binance's public-data specification](https://github.com/binance/binance-public-data/blob/master/README.md) states that spot `aggTrades` daily archives become available the following day, provides the eight-column layout, and publishes a companion `.CHECKSUM`. The frozen universe is `BTCUSDT, ETHUSDT, BNBUSDT, XRPUSDT, ADAUSDT, DOGEUSDT, SOLUSDT, LINKUSDT, LTCUSDT, TRXUSDT, DOTUSDT, AVAXUSDT`. No symbol is selected from subsequent performance.
- A GitHub Actions scheduled run at **04:17 UTC daily** (plus optional manual dispatch) checks up to seven completed UTC days, never before activation. [GitHub warns](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) that scheduled runs can be delayed and public-repo schedules can be disabled after inactivity. The actual capture timestamp is recorded; missing days remain missing until a later allowed fetch. A day is committed only when all 12 archives and checksum files pass. No raw ZIP or trade tape is retained after the job.
- Every official ZIP must match its SHA-256 `.CHECKSUM`, have exactly one expected CSV member, at most 128 MiB compressed and 512 MiB uncompressed, eight fields per trade, contiguous aggregate IDs, UTC microsecond timestamps inside the named date, finite positive price/quantity, and valid maker flags. Each of the 24 UTC hours per symbol needs at least one trade. Any violation aborts that date without output; no interpolation, guessed zeros or replacement venue. A missing official archive is retried only within the frozen seven-day lookback; later manual recovery would retain its true later `captured_at_utc` and cannot recreate a timely signal.
- The append-only output is one compressed JSON file per date at `Spot_Multi_Strategy/research/prospective/binance_vision_daily/YYYY-MM-DD.json.gz`. It contains per-symbol archive URL, ZIP hash and hourly **counts and quote notional**, plus capture timestamp and implementation commit. No price series, orders, account data, API keys, news text or personal data are stored. An existing date file is never overwritten. The GitHub workflow has only repository `contents: write` permission and commits only this source directory.

## Evidence limits and deployment reason

The local WebSocket journal activated 2026-11-09 and its first 39 due hours had **zero fully observed 12-symbol hours**: 37 invalid plus 2 unavailable per symbol at the read-only audit. macOS power logs showed repeated system sleep on battery during those hours. The local journal is preserved and was not backfilled; a compatible append-only late-message incident table was added after activation. This remote path avoids requiring the laptop to remain awake, at the cost of next-day archive delay. It supports later prospective **daily/next-day** signals, not minute execution, order-book depth, HFT fill proof, or five years of OOS today.

Long-run success still requires monitoring workflow failures, cross-day aggregate-ID continuity, archive revisions, actual venue execution costs and an independently preregistered strategy. The user's full CAGR/Sharpe/drawdown/PF Gate remains unpassed; all trading is disabled.

The read-only command `PYTHONPATH=Spot_Multi_Strategy python3 -m research.crypto_blackbox.binance_vision_daily_coverage` validates each committed summary, adjacent-day aggregate IDs, missing days and the longest continuous run. It never equates a source run with executable OOS or a passed trading Gate. The first successful scheduled capture can occur only after the activation day is complete and the exchange publishes its ZIPs.
