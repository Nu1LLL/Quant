# Mini-Medallion V1.1 — 结构性迭代（不是调参）

这是在[V1报告](../mini_medallion_v1/README.md)基础上的一次**结构性**
后续研究，回应"继续优化"但明确要求"改结构、不是回头调阈值让数字更
好看"。V1的原始数字保持不动（详见其README），本报告只新增/修正
以下三件事，并如实报告结果——**其中两件事的诚实结论是"没有帮助甚至
更差"，只有一件事（修正一个真实的未来数据泄漏bug）算是确定的改进**：

1. **修了一个真实bug**：D场景（regime过滤）原来用的
   `alpha_metrics.compute_regime_labels()`是用全样本分位数切分
   trending/mixed/ranging，这意味着2020年某根K线的分类依赖了2026年
   的数据分布——这是未来数据泄漏，违反了任务里"不允许未来数据泄漏"
   的强制要求。已修正：交易用途改成纯滚动窗口、逐bar只用过去数据的
   `compute_raw_efficiency_ratio`，并且把"硬切0/1"改成连续缩放
   （更符合本仓库其他风控组件——回撤打折也是连续的，不是开关式的）。
2. **尝试了逐笔ATR止损**（结构性新增，见下）：诚实结论是**没有改善
   最大回撤，反而因为频繁止损后重新入场（whipsaw）增加了换手和成本，
   风险调整后收益进一步下降**。
3. **诊断了为什么IC/相关性加权跑输等权**：不是因为过度集中在两个
   相关alpha上（实测平均权重其实相当均衡），更可能是因为这两种加权
   方式系统性地把更多权重给了A07（一个波动率regime特征，不是方向性
   动量信号），稀释了A02/A08两个真正方向性alpha的择时精度。

---

## 1. Bug修复：regime过滤的未来数据泄漏

### 问题

`alpha_metrics.compute_regime_labels()`用`efficiency_ratio.quantile([1/3, 2/3])`
在**整段历史**上计算三分位切分点，然后用这个固定切分点给每一根K线
分类。这个函数本身的文档一直写着"只用于研究报告里的regime细分展示，
不是一个交易规则"，但V1的`portfolio_backtest.py`里D场景（regime过滤
集成）却直接拿它的分类结果去决定实际仓位——这就是把一个"事后描述性
统计"误用成了"交易规则"，产生了真实的未来数据泄漏。

用测试证明了这个泄漏确实存在：
`tests/test_alpha_metrics.py::RegimeCausalityTests.test_regime_labels_can_change_when_future_data_is_appended`
——给同一段历史后面追加不同的未来数据，前400根K线的regime分类结果
会跟着变化，证明分类结果确实依赖未来数据。

### 修复

新增`alpha_metrics.compute_raw_efficiency_ratio()`：纯滚动窗口，
不做任何全样本分位数校准，t时刻的值只用t及更早的数据（用另一个测试
`test_raw_efficiency_ratio_is_unaffected_by_truncating_the_tail`验证）。
`portfolio_backtest.py`的D场景现在用这个连续值（范围[0,1]，效率比率
越高代表越像趋势市）直接**乘**在目标敞口上做连续缩放，而不是根据
硬分类的"ranging"标签把敞口砍成0。

### 修复前后对比（D场景，corr_penalized集成）

| | V1原始（有泄漏+硬切0/1） | V1.1修正（因果+连续缩放） |
|---|---|---|
| Sharpe | 0.020 | **0.185** |
| Sortino | 0.019 | 0.196 |
| 最大回撤 | -40.40% | **-18.34%**（比B自己的-27.14%还好） |
| 年化换手 | 32.74 | 13.63 |
| 总手续费 | 3287.40 USDT | 1368.85 USDT |
| CAGR | -0.37% | 1.05% |

**修复后确实变好了**：Sharpe从接近0提升到0.185，最大回撤从-40%降到
-18%（是目前所有主动策略场景里回撤最小的一个，比不加regime过滤的
B_corr_penalized本身的-27%还小）。这证明V1里D场景那么差，相当一部分
原因确实是"硬切换+未来数据泄漏"这个实现缺陷，而不是"regime过滤"这个
思路本身完全没用。

**但修复后仍然明显跑输不做regime过滤的B（Sharpe 0.185 vs 0.601，
CAGR 1.05% vs 6.94%）**，说明"用效率比率连续缩放敞口"这个具体做法，
即使实现正确了，代价也是显著牺牲收益换来更小的回撤——这本身也是一个
诚实的负面结论，不能反过来说"regime过滤经过修复后就成功了"。

## 2. 结构性新增：逐笔ATR止损（诚实结论：没有帮助）

### 动机

V1报告的"已知薄弱环节"第3条明确指出：新系统的组合层风控
（波动率目标+回撤打折）没有替代既有引擎逐笔ATR止损提供的下行保护，
这被认为是新系统最大回撤（-18%~-27%）远差于既有系统（-2.4%~-4.5%）
的主要原因。这是一个具体的、可检验的假设。

### 实现

`risk_overlay.py`新增`stop_loss_atr_multiple`（默认None，不启用）：
持仓期间跟踪"入场以来收盘价峰值"，用ATR标准化的回撤幅度判断是否
强制平仓。这是engine.py日内最低价止损的**简化近似**——只在4小时
K线收盘时检查，保护力度更弱，这一点在代码注释里明确记录。止损判定
优先于换手不交易带（不会因为"变化幅度不够"而忽略止损）。

单元测试覆盖：止损确实降低回撤下限
（`test_stop_loss_forces_exit_and_caps_drawdown`）、关闭时不触发
（`test_no_stop_loss_when_multiplier_is_none`）、能突破不交易带
（`test_stop_loss_overrides_no_trade_band`）、因果性
（`test_stop_loss_is_causal`，篡改未来价格不影响过去的止损判定）。

### 在真实数据上的结果：假设没有得到支持

用`configs/trend_champion.json`同款的`trend_stop_atr_multiple=2.5`
（既有引擎自己的默认值，不是从回测结果里挑出来的数字）：

| | B（无止损，corr_penalized） | E（同样的组合+ATR止损2.5倍） |
|---|---|---|
| Sharpe | 0.601 | **0.528**（更差） |
| 最大回撤 | -27.14% | **-29.74%**（更差） |
| 年化换手 | 14.85 | 19.47（更高） |
| 总手续费 | 1490.52 USDT | 1954.38 USDT（更高） |

补充做过一次多个倍数（1.5/2.0/2.5/3.0）的扫描（仅用于确认这不是
2.5这一个点的偶然结果，不是为了挑一个好看的倍数使用）：**从1.5到
3.0倍，Sharpe和最大回撤单调地随止损收紧而变差**，没有任何一个测试
过的倍数比不设止损更好。完整数据见本目录`stop_loss_sensitivity.csv`。

### 为什么会这样：一个合理的解释（不是确定结论）

这套组合的"信号"是连续的组合alpha分数，不是engine.py那种离散的
"突破进场、明确条件离场"交易。给连续敞口叠加逐笔止损后，只要标的
下跌触发止损，敞口被打到0；但如果alpha信号本身还没转向（继续给出
正的目标敞口），下一根K线（或不久之后）就会重新建仓——这样在下跌
趋势里可能反复"止损—重新进场—再止损"，即经典的止损反复打脸
（whipsaw）。既有引擎的止损之所以有效，可能是因为它绑定在一套
"离场后需要新的突破条件才能再次进场"的离散信号逻辑上，而不是止损
机制本身天然有效——**这里的负面结果提示"止损"和"连续敞口alpha信号"
这两种设计范式可能不能简单拼接，需要更深层的结构调整（比如止损后
增加冷却期、或者止损期间同时压低alpha信号本身），而不是这次V1.1
测试的"止损后信号一旦转正立刻允许重新进场"这种最简单实现**。

## 3. 诊断：IC/相关性加权为什么跑输等权

### 观察

V1报告发现IC加权（Sharpe 0.616）和相关性惩罚加权（Sharpe 0.601）
都跑输等权（Sharpe 0.948）。一个自然的猜测是"IC加权把太多权重集中
在两个相关性0.73的alpha（A02/A08）上"，但实测平均权重并不支持这个
猜测：

| 方法 | A02_ema_distance_100 | A07_atr_percentile | A08_trend_quality |
|---|---|---|---|
| 等权 | 33.3% | 32.7% | 33.6% |
| IC加权 | 26.1%-28.2% | **40.8%-41.3%** | 30.1%-32.7% |
| 相关性惩罚加权 | 25.3%-27.5% | **42.6%-43.0%** | 29.1%-31.7% |

（BTCUSDT/ETHUSDT两个品种的区间）

平均权重其实相当均衡，IC/相关性加权甚至给了A07更少相关的信号更高
权重（约41%-43% vs 等权的33%），这正是"相关性惩罚"设计想要的效果。
**问题不在"过度集中"，而更可能在于A07的经济含义和A02/A08不同**：
A07是ATR分位数（一个波动率regime特征，"最近波动率处于历史什么位置"），
不是方向性的价格动量测量；把接近40%的权重放在这样一个信号上，
会稀释组合分数里真正代表价格方向判断的成分（A02/A08），可能导致
组合在真正应该顺势加仓的时刻反而因为A07的权重被拖累。

**这是一个合理的解释，不是确定结论**——要真正证实，需要做"固定权重
消融实验"（比如只用A02+A08两个方向性alpha做等权，对比加入A07前后
的表现），受限于本次迭代的时间没有展开，留作后续工作。这里如实
标注为"可能的解释"而不是"已证实的原因"。

## 4. 结论

| 检查项 | V1 | V1.1 |
|---|---|---|
| 是否有可重复的alpha预测能力 | 3/58通过4h门槛，1h全灭 | 不变 |
| 组合层是否有未来数据泄漏 | **有**（D场景regime分类） | **已修复** |
| 组合Sharpe是否优于既有系统 | 否 | 否（修复后D也不例外） |
| 逐笔止损是否改善回撤 | 未测试 | **测试后：没有，反而更差** |
| 是否具备模拟盘资格 | 否 | **仍然否** |

修复未来数据泄漏是本次迭代唯一确定的改进（本身有独立价值，即使
它没有让最终结论从"不达标"变成"达标"）。逐笔止损这个结构性思路
被证伪，IC/相关性加权劣于等权的现象有了一个合理但未证实的解释。
**这次迭代没有改变V1的核心结论：新系统仍然不具备进入模拟盘的资格。**
按照任务要求，不应该为了让数字更好看而继续调整阈值或反复尝试止损
倍数——下一步如果要继续，应该针对第3节提出的"消融实验"或第2节
提出的"止损+信号冷却期"做真正的结构性设计，而不是在现有结构上
搜索参数。
